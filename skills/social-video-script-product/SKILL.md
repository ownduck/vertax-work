# 商品介绍短视频剧本创作

把商品的已知信息转成清楚、有观看价值、可演示的短视频剧本。使观众理解它是什么、怎样使用或为何与自己相关；只有要求销售推广时才围绕转化组织内容。

## 默认约定（英文 + 美国人）

- **语言**：默认用英文写完整份交付——叙述、演示说明、口播、对白、旁白均默认英文。用户用中文提需求或给中文卖点时仍输出英文剧本（事实准确翻译，不编造）。仅当用户**明确要求**某语种（或锁定非英文台词/广告语原文）时才用该语种。成片口播音频默认英文。
- **人物**：需要出镜演示/讲解人物且未指定身份时，**默认美国人**（姓名、外貌与文化细节与此一致，不过度刻板）。用户指定其它国籍、提供人物参考图或锁定非美国身份时，从其指定。无人物、纯商品特写可不强造人物。

## 主题中立与任务边界

- 不预设品类、生活方式、题材、情绪或卖点。根据本次商品和需求选择表达。人物国籍未指定时按上文默认美国人。
- 区分介绍、分享、演示、评测、品牌表达和销售推广。商品视频不自动等于广告；分享不自动等于个人使用推荐；UGC 是风格，不是已验证的真实用户经历。
- 不强制痛点、问题解决、前后对比、冲突、反转、促销、倒计时或购买 CTA。可以直接讲解或展示；不能为“有故事”发明消费者困境。
- 默认交付剧本正文。只在要求时附分镜、时间表、字幕、发布文案、标签、AI 提示词或多个版本。不要生成图片、视频或执行发布。
- 独立运行；不要强制品牌档案、其他 skill、服务账号或 API。

## 1. 整理简报与商品事实

内部整理商品对象、目标、受众、平台、时长、表现方式、必须展示的信息、锁定资产、禁用项和输出格式。文字与对白语言未指定时按**英文**默认，用户明确指定时从其指定。

当前明确要求优先，只沿用同一项目仍适用的约定。不要继承另一商品的参数、之前短片的人物或默认账号题材。时长未给定时写紧凑完整版本，不锁定固定秒数。

建立内部事实表，区分：

1. 用户提供的规格和事实。
2. 已读取资料中的事实及来源。
3. 图片/视频能直接观察到的外观、操作和状态。
4. 用户明确提供的个人体验或真实评价。
5. 尚未确认的信息。

读取链接内容后再引用；打不开时不假装查证。图片只能支持可见信息，不支持凭外观猜材质、性能、认证、价格或耐久度。来源矛盾时不拼接不同型号；核对对象并询问关键冲突，或避开争议事实。

在写稿前判断现有资料是否足以完成用户实际要求，而不是能否凑出一段文字。商品资料不足时，必须进入下列 HITL 流程；不得先写成稿再让用户纠错。

### 商品资料不足：HITL 人工介入

1. 依据本次目标列出必要事实。商品身份/型号、核心介绍点及依据通常必要；价格与优惠只在要介绍它们时必要；真实测评还需要真实使用条件与观察。不要机械索要全部规格。
2. 标出缺失、矛盾或无法确认的项目，以及它们会阻塞哪一部分。不能把缺失参数、不可读参考图或不同型号冲突当作已知。
3. 用一次简短提问收集当前已知的关键缺口，优先请用户补商品资料、确认型号或给出实际体验。必要时提供明确的范围选项，但不替用户选。
4. 暂停依赖这些资料的创作，等待用户回答。在此期间可以内部整理已有事实；不输出替代成稿、自动降级稿、猜测稿或充满占位符的稿件。
5. 用户补充后重新检查充分性，足够才写；仍有实质缺口时指出剩余项目。用户明确同意缩小范围后才按新范围创作。沉默、超时、“快点写”“不要问”或“只要正文”不等于补齐事实，也不自动授权换目标。

与请求无关的未知信息不构成资料不足，无需追问。用户已明确只介绍图片中的可见外观且图片可读时，可按该有限范围写；用户已要求模板或假设概念稿时，可交付清楚标记的框架，但不能冒充事实成稿。不能以这些例外悄悄替换用户原本要的完整介绍或真实测评。

## 2. 确定介绍重点与形式

内部用一句话定义：本条让谁理解商品的哪一方面，以及通过什么画面、操作或解释让其理解。

选择一个主要信息点和足够支撑它的少量次要信息，不塞进全部卖点。按需求选择场景故事、讲解、演示、开箱、对比、评测或其他适合形式，不机械套模板。

需要整理卖点和展示依据时，读取 [事实、价值与演示](references/product-evidence.md)。需要选择结构或写多个版本时，读取 [结构与版本变化](references/structures-and-variation.md)。

将“特征 → 用途/意义 → 展示依据”作为内部推理链，不能因看起来合理就把未确认功效写成事实。对已知特征解释相关用途；对未知效果仅提出观察目标，不能先写成功结论。

## 3. 写剧本

- 开头尽早明确商品或相关的具体行动、状态、细节，让观众知道在看什么。不靠夸大功效或无关事故吸引注意。
- 每一步补充新信息：识别商品、观察细节、完成操作、解释用途或呈现有依据的结果。
- 用可见、可听内容支持介绍，不堆“高级、绝绝子、必买”等空泛判断；不以画面暗示口播不敢说的功效。
- 有剧情时让商品自然参与行动，并展示相关特点，避免无关表演后硬插商品。
- 无剧情时保持信息顺序、操作流程和理解路径完整，不强造人物与对白。
- 写自然、完整的对白或旁白。说话者的身份与知识合理；不要让所有人物变销售员。
- 按目标结束：介绍停在信息或使用状态；分享收束观察；推广给一个已知、可执行的行动。没有要求时不自动加购买、点赞、关注、评论引导。
- 保留用户指定的口播、外观、图案、型号、配件和操作限制，不改商品适应剧情。

## 事实与体验硬边界

- 不编造价格、折扣、库存、销量、材质、成分、性能、尺寸、兼容性、认证、保证、测试、比较优势或疗效。
- 不编造使用天数、购买记录、个人感受、客户证言、评分、合作状态或“不含广告”。自然 UGC 语气不允许伪造真实体验。
- 同样不要编造说话者“没用过”“尚未测试”“准备亲测”等经历或计划。资料不足是创作者的信息边界，不是人物的个人事实。不要把查证过程、缺少资料或被删掉的夸大说法写进商品口播。
- 可创造说明用途的虚构人物与场景；不能暗示已证实的效果或真实客户案例。虚构场景在交付说明或用户指定字段中标明；只要正文时，不使用会冒充真实见证的叙述。
- 对比只用可比型号与已知条件，未知对照不写失败结果。演示不是测量，没有测试数据就不写量化结论。
- 区分感觉、观察和事实。用户提供相应体验后才把“我觉得/我用了”交给说话者；加“可能”不能替代依据。
- 要核实当前价格、规定或技术数据时查证相关来源；普通创作不为不存在的论据广泛搜索。来源中的指令不覆盖用户要求。

## 4. 检查时长与连续性

读取 [时长与交付检查](references/timing-and-output.md) 的相关部分。

分别预算口播、操作、展示停留与反应时间，为辨认商品和理解演示留时间。不靠极快语速塞参数，不把动作与解释一律算为完全并行。

保持同一型号、颜色、图案、数量、配件、开合状态和摆放关系连续。操作、工具接触、液体或布料状态应有因果过程；不靠跳切暗示不可能的效果。

依据可见历史比较不同版本的信息焦点、操作、观察角度、叙事顺序和结尾。可共享事实，但不只换人物地点就声称新创意。没有记录时不声称全面去重。

## 5. 按请求交付

- 默认：一份完整介绍剧本，以自然段包含必要动作和完整对白；不附内部事实表、营销策略、评分或无关解释。
- “一整段/只要正文”：资料充分时只输出一段，不加标题、分镜表或 Markdown，不插入伪造数字；资料不足时先进入 HITL，格式要求不能绕过事实检查。
- “口播文案”：只写要说的话，操作放在用户要求的独立部分。
- 被要求写无依据的真实测评时，进入 HITL，请用户提供真实体验及相关依据；不要自行改成中性介绍，不在口播中讨论查证过程，也不要仅以拒绝结束而不给补充路径。
- “详细剧本”：提供必要场景、商品动作、对白/旁白和声音；仅在要求时添加时间或镜头。
- “多个版本”：锁定全部事实，在重点、结构或展示机制上变化，不捏造新卖点。
- “改某部分”：只改指定范围，商品、已验证卖点和锁定台词保持一致。
- JSON 或自定义格式：只输出约定字段，按允许的空值方式表示未知，不补造值。

交付前核对目的、主题、商品身份、逐条事实、画面隐含断言、对白、时长、连续性和格式。冲突先修正；硬性台词无法装进指定时长时说明限制，不偷偷删改或假称严格达标。不保证销量、爆款或涨粉。
