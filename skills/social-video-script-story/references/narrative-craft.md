# 叙事与变化

## 选择结构，不选择固定主题

根据用户意图选择组织方式。下列是可选工具，不是强制模板或轮换配额。

| 内容需要 | 可用组织方式 | 检查重点 |
|---|---|---|
| 主体采取行动 | 当前状态 → 意图/行动 → 反馈 → 新状态 | 行动是否有动机，反馈是否改变后续 |
| 发现或理解 | 具体观察 → 新线索 → 认知变化 | 观众能否看到线索，发现是否成立 |
| 关系变化 | 互动 → 回应 → 关系状态改变 | 人物是否互相回应，而非轮流念稿 |
| 一个过程 | 初始状态 → 关键阶段 → 完成/中断状态 | 材料或对象是否连续，阶段有无区别 |
| 一段经历 | 关键事件 → 必要背景 → 经历与结果 | 事实边界、讲述视角和时间顺序 |
| 感受或氛围 | 视觉/声音母题 → 细节变化 → 感受落点 | 是否有具体感知对象，而非空泛形容 |

故事不必同时具备目标、障碍、冲突、反转、教训。选中的结构应服务请求，不能决定作品主题。

## 把推进写清楚

对每个关键事件问：发生前是什么状态？谁做了什么？为什么做？哪一点因此改变？下一步如何受到影响？

人物戏用因果联系，过程与感受型内容用状态或观察联系。若删掉一段完全不影响后续和体验，优先删掉它。

识别信息位置：观众比人物知道更多、人物比观众知道更多，或同时发现。选择适合的关系并保持；不要为了反转突然改变视角，使前文变成欺骗。

## 开头与结尾

从故事本身提取具体的入场点，而不是外挂“你绝对想不到”之类空话。行动、细节、声音、一句对白或一段观察都可以是开头。

结尾可以完成行动、落定关系、显示变化、揭示信息、保留余韵或按要求未完待续。只有适合时才使用笑点、反转或循环。埋伏笔时确保第一次观看也能理解基本故事；不要靠故意信息过载制造重看。

## 多版本与重复判断

内部比较：

- 主体与关系；
- 触发条件或观察对象；
- 核心行动链；
- 观看视角和信息揭示顺序；
- 结束状态与回报机制。

用户要求新故事时，优先变化核心行动链或回报机制，并改变至少一个其他关键维度；用户锁定故事只要换开头时，保持故事并变化入场点即可。不要为了查重擅自解除固定角色、场景或主题。

未知历史不是已检查历史。可建议用户维护一句话故事索引，但不把提供索引作为创作前置条件。
