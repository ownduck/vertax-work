# 通用短视频故事剧本创作

把用户的创作意图写成完整、连贯、适合短视频表达的故事。优先保证人物行为、事件因果和观看体验，再优化开头与节奏。不要把留存技巧写成固定题材或故事公式。

## 默认约定（英文 + 美国人）

- **语言**：默认用英文写完整份交付——叙述、动作说明、口播、对白、旁白均默认英文。用户用中文提需求时仍输出英文剧本；不要默认交中文成稿。仅当用户**明确要求**某语种（或锁定非英文台词原文）时才用该语种。成片口播音频默认英文。
- **人物**：未指定国籍/族裔/外观参考时，**出场人物默认美国人**（姓名、外貌与文化细节与此一致，不过度刻板）。用户指定其它国籍、提供人物参考图或锁定非美国身份时，从其指定。

## 主题中立与任务边界

- 从当前需求提取主题、类型、情绪、真实性、受众和表现方式；没有指定时保持开放。不要默认日常尴尬、宠物、爱情、励志、悬疑、搞笑或任何既有账号赛道（人物国籍默认美国人除外，见上）。
- 当用户把主题选择交给你时，主动选择一个具体创意完成作品；不要把一次创意变成以后所有作品的默认方向。
- 区分主题、类型、语气、结构和形式。口播不等于经验分享，无台词不等于解压，涨粉不等于搞笑，短视频不等于反转短剧。
- 不强制冲突、反派、误会、道德教训、反转、悬念、循环、快切或 CTA。按故事需要选用；观察、过程、关系变化也能构成有效推进。
- 默认交付剧本正文。只在用户要求时提供分镜、时间表、生成提示词、字幕、发布文案、标签或多个版本。不要调用图片/视频生成或发布工具。
- 独立运行；不要要求安装其他技能、填写品牌档案或连接服务。仅在必要时读取用户提供的参考材料。

## 1. 锁定创作简报

内部整理，不把空白问卷交给用户：

- 已知主题或素材、目的、平台与受众、时长；文字与对白语言未指定时按**英文**默认，用户明确指定时从其指定。
- 人物与关系、场景、已有情节、必须发生的事件、禁止项、参考素材及其用途。
- 真实纪实还是虚构；真人拍摄还是 AI 制作；请求范围是故事、口播、对白、局部修改还是详细剧本。
- 锁定的台词、事件顺序、结尾、角色外观及输出格式。

当前明确指令优先，其次采用同一项目仍适用的约定。不要把另一个账号、另一条故事或参考文件中的主题与人物迁入本次任务。

信息足以创作就直接写。用户要求自由创作时不追问主题；补充可撤销的创意细节。仅当关键缺口使结果无法成立时，一次问最少必要问题。时长未给定时，先写紧凑完整短篇，不把某个秒数固定为技能默认。

读取提供的链接或文件后再使用其内容；读取失败时说明局限，不声称已参考。保留锁定内容；修改指令不明确时采用最小必要改动。

## 2. 确定故事核心

内部用一句话说明：主体经历了什么，以及结束时发生了什么变化或获得了什么发现。过程型作品可以用完成状态或感知变化作终点，不必创造戏剧冲突。

确定观看视角、人物知道的信息和观众知道的信息。角色动作来自当下目标、处境或观察；不要让角色为了迎合结尾做出无动机行为。

开放创作时，内部形成少量不同机制的候选，按意图匹配、可理解性、原创性和时长可行性选择一个。用户只要一个剧本就只输出一个，不展示推演过程。

需要选结构、组织多版本或查重时，读取 [叙事与变化](references/narrative-craft.md)。把结构作为诊断工具，不把每条都套成同一种情节。

## 3. 写出可见、可听的推进

- 尽早呈现最有价值的信息、行动、状态或关系，不用无意义开场拖延。开头可以安静，但必须有具体内容。
- 用事件或细节推进下一步。每一段至少改变行动、认知、关系、情绪或过程状态，删掉只换说法的重复。
- 用可见行为表达抽象情绪。关键变化要有准备或铺垫，避免无来由的巧合解决一切。
- 按需求选择现场对白、旁白或无言动作。无台词版靠画面关系完成理解；不要偷偷补字幕承担叙事。
- 让对白具有回应关系、人物语气和现实说话长度，避免所有角色都像旁白。反应、停顿和身体动作也占时间。
- 让结尾完成本条承诺，或按要求留下明确的未解问题。反转要有铺垫；循环要有意义；不要默认解释笑点、总结道理或喊关注。
- 镜头与音效只写到理解故事所需的程度。普通故事文案不堆焦段、摄影器材、曝光或模型参数。

## 4. 检查时长、连续性和原创性

读取 [时长与交付检查](references/timing-and-output.md) 的相关部分。

分别估算实际对白/旁白、动作、反应和场景变化；时间标签不是完成时间的证据。目标越短，越要减小信息量，不能靠加速念完或省掉理解所需的反应强塞情节。

保持人物、衣着、空间、物件数量、持有者、位置和状态连续。现实题材遵守物理与行为逻辑；非现实题材遵守已建立的世界规则。无脸版不依赖面部表情，无声版不依赖声音，无字幕版不依赖屏幕字。

根据可见历史或用户记录比较：主体关系、触发事件、主要行动链、结构和结尾机制。仅换名字、地点、道具或措辞不算全新。没有记录时只保证本次与已知素材不同，不声称检查过全部旧稿。

虚构作品可以创造人物和事件。纪实、真实经历或历史故事不编造事实、证词和数据；不要把虚构经历说成用户亲历。借鉴参考的结构或节奏，不复制独特情节与台词。

## 5. 按请求交付

- 默认：一份完整剧本，以自然段写清发生的事情，必要时嵌入完整对白；不附分析、结构标签、评分、营销话术或使用说明。
- “一整段/只要正文”：只输出一段文本，不加标题、分镜、表格、Markdown 或代码围栏。
- “口播文案”：只输出要说的话，不混入演员无法朗读的动作备注。
- “详细剧本”：按要求提供场景、动作、对白和必要声音；需要时间节点时再添加。
- “多个版本”：保持锁定项，各版本在行动链、叙事角度、信息揭示或结尾上实质不同。
- “改这句/优化开头”：只处理指定范围，不为局部优化擅改完整故事。
- JSON 或自定义格式：严格遵循字段、类型和空值规则，不插入额外说明。

交付前内部检查主题与请求一致、因果或过程成立、对白自然、结尾兑现、时长可行、连续性完整、格式符合。修正问题后直接交付；硬性台词与时长不可兼得时，简短指出冲突并给出最接近要求的方案，不悄悄删改锁定内容。
